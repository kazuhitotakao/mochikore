# もちこれ 開発規約（案）

2026-11-05 時点の案です。2026-11-09に環境構築（手順書第9章まで）を終えましたが、機能はまだ実装していないため、実際に動かして確認した規約ではありません。
試作や実装で分かった事実は、この規約へ反映します。

- **★** が付いたルールは、CLAUDE.md へ写す候補です。
- **（仮）** が付いたルールは、付録Bの確認が終わるまで変わる可能性があります。

## 0. この規約の使い方

### 0-2. この規約の前提になっている決定

| 項目 | 決定 |

| トークン更新 | 初期版では実装しない（D-74）。API-35は追加しない |

| Next.jsの窓口 | Laravel APIとの通信窓口は原則Route Handlerに統一する。Server Actionsは初期版のAPI通信に使わない。例外はServer Componentの読み取りだけで、Next.jsのサーバーから直接Laravelへ送る（D-76） |
| 優先度 | API-29、`group_id`、`grouping_revision`、`packing_list_groups` は必須。SC-09とAPI-30は追加のまま。F-17とAPI-26はSC-11と同時に作る（D-79） |
| 401の扱い | Cookieがなければログイン前として表示する。公開画面では401でも移動しない（D-80） |
| 開発環境 | テスト用DB、Prettier、日本語の文言、`.env.example`、画面のURLの扱いはD-81のとおり |
| 設計書の参照 | GoogleスプレッドシートとNotionをClaude Codeから直接参照する。設計書と手順書を正本とし、複製を常時管理しない（D-77） |
| 開発コンテナ | VS Codeで入る作業用のworkspaceコンテナ（PHP + Node）に、髙尾工房と同じ拡張機能49個・alias・Claude Code・Codex・GitHub CLIを入れる。frontend・backendのコンテナは開発サーバーを動かすだけにする。`docker compose` が必要な操作はMacのターミナルで行う（D-88、手順書第3・9章） |
| 公開の切り替え | 編集途中で公開にするときは、未保存の入力を先に保存してから公開する。非公開にするときはすぐ切り替える（D-85） |
| 作成日時・更新日時 | 7つのテーブルにLaravel標準の `timestamps()` を作る（D-86） |

### 1-1. Git

### 1-3. 環境変数・秘密情報

| ルール | 理由 |
|---|---|
| ★ `.env` 類はコミットせず、`.env.example` に項目名だけ書く | 手順書第4章 |

| ★ `APP_KEY` を再生成しない | 手順書第6章 |
| 本番の値はVercel・Railwayの環境変数に入れる | リポジトリに残さない |


| ルール | 理由 |

### 2-3. 役割

| 場所 | 書くこと | 書かないこと |
|---|---|---|
| FormRequest | 入力の形・長さ | 件数の上限、本人確認 |
| Controller | 認可 → 処理の呼び出し → 応答 | 業務ルール、トランザクション |
| Service | ロック、上限、`grouping_revision`、複数テーブルの更新 | Request・Response |
| Policy | 本人のものかの判定 | 入力チェック |
| Model | リレーション、型変換 | 業務の手順 |
| Resource | 返す項目 | 取得処理 |

- ★ **Serviceは必要なときだけ作ります。** 単純な1件の取得や更新は、ControllerからModelを直接使います。
- ★ **Repository層は作りません。** Eloquentがデータ操作の役割を持つため、層を増やす利点が小さいからです。

```php
class PackingListItemController extends Controller
{
    public function store(StoreItemRequest $request, PackingList $list, PackingListItemService $service)
    {
        Gate::authorize('update', $list);

        // 新しく作ったデータを返すと、Laravelが201にする
        return new PackingListItemResource(
            $service->add($list, $request->validated('name'))
        );
    }
}
```

```php
class PackingListPolicy
{
    public function update(User $user, PackingList $list): Response
    {
        return $user->id === $list->user_id
            ? Response::allow()
            : Response::denyAsNotFound(); // D-43
    }
}
```

### 2-4. Form Request

| ルール | 理由 |
|---|---|
| ★ `$request->all()` を使わず `validated()` だけを渡す | 想定外の項目の保存を防ぐ |
| 条件は06_API詳細に合わせる | 仕様の基準を1つにする |
| `authorize()` は `true` のままにし、認可はControllerで行う | 確認の場所を統一する |
| API-11で `group_id` を受け取らない | 設計の決定 |
| 入力エラーの文言は `lang/ja/validation.php` に日本語で用意する | `APP_LOCALE=ja` にするため（D-81） |

### 2-5. API Resource

| ルール | 理由 |
|---|---|
| ★ 応答はResourceで返し、Modelをそのまま返さない | 余計な項目が出るのを防ぐ |
| ★ 公開用は別のResourceにする | 作成者の情報やチェック状態の漏れを防ぐ |
| 項目名はsnake_caseのまま返す | D-55 |
| 返すデータがないときは `response()->noContent()` を使う | D-62 |

Resourceは標準で `data` に包まれ、ページ分割では `links` と `meta` が付きます。D-53と同じ形なので、設定は変えません。

### 2-6. エラー・例外

★ エラーは必ず `message` と `code` を返します。16種類のコードは `ApiErrorCode` にまとめます。

```php
class ApiException extends RuntimeException
{
    public function __construct(public ApiErrorCode $errorCode, string $message)
    {
        parent::__construct($message);
    }

    public function render(): JsonResponse
    {
        return response()->json([
            'message' => $this->getMessage(),
            'code' => $this->errorCode->value,
        ], $this->errorCode->status());
    }
}
```

Laravel標準の例外は、`bootstrap/app.php` でまとめて変換します。

| 元の例外 | 変換先 |
|---|---|
| 入力エラー | 422 `validation_error` |
| 未ログイン・期限切れ | 401 `unauthenticated` |
| 回数制限 | 429 `too_many_requests` と `retry_after` |
| 署名付きリンクの403 | 422 `link_invalid` |
| 想定外のエラー | 500 `server_error`（詳細は返さない） |

メール未認証の403には `code` が必要です。標準の `verified` の代わりに、ApiExceptionを投げる自作のミドルウェアを使います。

### 2-7. Eloquent

| ルール | 理由 |
|---|---|
| Modelの設定は `#[Fillable]` など、生成時と同じ書き方にする | Laravel 13の標準 |
| ★ 一覧は `with()`・`withCount()` で読み、N+1を防ぐ | 1件ごとの追加問い合わせで遅くなるのを防ぐ |
| 開発中は `Model::preventLazyLoading()` を有効にする | N+1にすぐ気づける |
| ★ `$touches` を使わず、親の更新はServiceで明示する | D-25。チェックだけでは親の日時を変えない |
| ★ 持ち物の構造を変える処理は、親リストをロックしてトランザクションで行う | D-59 |
| ★ API-25のルートに `withTrashed()` を付ける | 付けないと削除済みの持ち物を取得できない |
| 上限値はModelの定数にまとめる | 同じ数字を散らさない |

```php
return DB::transaction(function () use ($list, $name) {
    $locked = PackingList::whereKey($list->id)->lockForUpdate()->firstOrFail();

    if ($locked->items()->count() >= PackingList::MAX_ITEMS) {
        throw new ApiException(ApiErrorCode::ItemLimitReached, '持ち物は200件までです。');
    }

    $item = $locked->items()->create([
        'name' => $name,
        'sort_order' => (int) $locked->items()->max('sort_order') + 1,
    ]);
    $locked->increment('grouping_revision');

    return $item;
});
```

### 3-3. コンポーネントの分割

- 分けるのは「2か所以上で使う」「`use client` の範囲を小さくできる」ときだけです。
- 確認ダイアログや通知など、02_画面配置の「共通」にある部品は `components/` に置きます。

### 3-4. Server ComponentとClient Component

Cache Componentsは使いません（D-75）。`next.config.ts` に `cacheComponents` と `partialPrefetching` を追加しません。

| ルール | 理由 |
|---|---|
| ★ 既定はServer Componentにし、操作が必要な部品だけ `'use client'` にする | ブラウザへ送るJavaScriptが減る |
| ★ 読み取りはServer Componentから `lib/api/server.ts` を通してLaravelへ送る | 公式はRoute Handlerを経由しない形を勧めている。D-76の例外 |
| ★ 更新はClient Componentから `/api/...` のRoute Handlerを通す | 窓口の処理を1か所にする（D-76） |
| ★ Server Actionsを初期版のAPI通信に使わない | D-76。チェックの連続操作にも向かない |
| ★ 表示の処理の中で更新系APIを呼ばない | 公式が禁止している。SC-04・SC-13は画面を開いた後に呼ぶ |
| ★ `params`・`searchParams`・`cookies()` は `await` する | Next.js 16で必須 |
| ★ 本人のデータをキャッシュしない | 他人のデータが見えるのを防ぐ |
| ★ 復元候補とSC-09の下書きは `useState` に置き、ブラウザへ保存しない | D-28、API-30 |
| ★ 認証が必要な画面への `Link` は `prefetch={false}` にする | D-36。先読みで期限を延ばさない |
| `proxy.ts` だけで画面を守らない。`middleware.ts` も使わない | 公式の注意 |

| 画面 | 種類 |
|---|---|
| SC-01、SC-16 | Server |
| SC-05、SC-10、SC-11 | Serverで取得し、操作部品だけClient |
| SC-07、SC-08、SC-09、入力画面 | Client |

### 3-5. Route Handlerの共通処理

★ ブラウザからLaravelへの通信は、次の順番で処理します。1から6は `lib/api/forward.ts` にまとめ、画面ごとに書きません。

| 順番 | 処理 | 説明 |
|---|---|---|
| 1 | Origin確認 | 更新系（POST・PATCH・PUT・DELETE）で、送信元が自分のサイトか確認する |
| 2 | 許可の確認 | `lib/api/routes.ts` にあるHTTPメソッドとURLだけを通す |
| 3 | Cookieの処理 | HttpOnly CookieからトークンをLaravel用の `Authorization: Bearer` へ移す |
| 4 | 操作の印 | 利用者の操作のときだけ `X-User-Activity` を付ける |
| 5 | 転送 | タイムアウトを付けてLaravelへ送る。転送元のヘッダーをそのまま渡さない |
| 6 | 応答 | 401のときはCookieを削除する。応答の形は変えず、204は本文なしで返す |

```ts
// src/app/api/[...path]/route.ts
import { forwardToLaravel } from '@/lib/api/forward';

export async function POST(request: Request, ctx: RouteContext<'/api/[...path]'>) {
  const { path } = await ctx.params;
  return forwardToLaravel(request, path);
}
// GET・PATCH・PUT・DELETE も同じ形
```

トークンを扱うAPIは、共通の窓口とは別のファイルにします。

| Route Handler | 処理 |
|---|---|
| `login`・`register` | Laravelの応答からトークンを取り出してCookieへ保存し、ブラウザへは `user` だけ返す |
| `logout` | Laravelのトークンを無効にしてCookieを削除する |
| `me` の `DELETE` | 退会に成功したらCookieを削除する |

Cookieの設定は次の案です。第11章の試作で確定します。（仮）

| 項目 | 案 |
|---|---|
| HttpOnly | 有効 |
| Secure | 本番で有効。ローカルのHTTPでは無効 |
| SameSite | `Lax` |
| 期限 | ログインから1年（D-78）。D-74でトークンを更新しないので、180日にすると使い続けている人のCookieが先に切れる |

`X-User-Activity` の付け方は次のとおりです。

| 経路 | 印 |
|---|---|
| 画面を開くときのServer Component | `serverApi` に `userActivity: true` を指定する |
| 利用者の操作によるブラウザからの通信 | `clientApi` が付け、Route Handlerが転送する |
| 自動処理・先読み | 付けない |

### 3-6. API通信

| ルール | 理由 |
|---|---|
| ★ `fetch` を画面に直接書かず、`lib/api/` を通す | 認証やエラーの扱いをそろえる |
| ★ `lib/api/server.ts` と `forward.ts` は `server-only` にする | ブラウザ用のコードへ混ざるのを防ぐ |
| データ取得のライブラリは入れない | 定期更新がなく、`fetch` で足りる |
| Cookieがないときは、API-04を呼ばずログイン前として表示する | 不要な401を出さない（D-80） |

```ts
// lib/api/server.ts
import 'server-only';
import { cookies } from 'next/headers';

export async function serverApi<T>(path: string, { userActivity = false } = {}): Promise<T> {
  const token = (await cookies()).get(AUTH_COOKIE)?.value;
  const res = await fetch(`${process.env.LARAVEL_API_BASE_URL}/api${path}`, {
    headers: {
      Accept: 'application/json',
      ...(token && { Authorization: `Bearer ${token}` }),
      ...(userActivity && { 'X-User-Activity': '1' }),
    },
    cache: 'no-store',
    signal: AbortSignal.timeout(5000),
  });
  return parseApiResponse<T>(res);
}
```

```ts
// lib/api/errors.ts
export async function parseApiResponse<T>(res: Response): Promise<T> {
  if (res.status === 204) return undefined as T; // D-62：JSONを読まない

  const body = await res.json();
  if (!res.ok) throw new ApiError(res.status, body.code, body.message, body.errors, body.retry_after);
  return body.data as T; // ページ分割のAPI-15は meta・links も返す形にする
}
```

### 3-8. エラー処理

★ `message` の文章では判定せず、必ず `code` を見ます（D-53）。

| 応答 | 画面の動き |
|---|---|
| 401 | ログインが必要な画面ではSC-02へ移動し、自動で送り直さない。公開画面では移動せず、ログイン前として表示を続ける（D-80） |
| 403 `email_not_verified` | SC-04へ移動 |
| 404 | 「ページが見つかりません」 |
| 409 | 読み直しを案内し、自動で送り直さない |
| 422 `validation_error` | 入力欄の下に表示 |
| 422 その他、403 `list_moderated` | `code` ごとに決めた文言を表示 |
| 429 | `retry_after` で残り秒数を表示 |
| 500・通信失敗 | 共通の文言を表示し、入力を残す |

★ 保存が終わる前に「保存できた」と表示しません。
